# Personal-only privacy policy

This repository and its associated personal GitHub account are for personal
material only. This is a strict privacy boundary, not just a secrets policy.

## Rules for every coding agent and contributor

- Do not include or imply employer names, employment details, job titles,
  organization affiliations, colleagues, clients, or work activities. This
  includes non-secret information and details already public elsewhere.
- Do not publish work email addresses, domains, internal URLs, repository names,
  local paths, identifiers, configuration, logs, screenshots, or documents.
- Do not copy or adapt work-derived code, data, architecture, business processes,
  or examples. Removing names or changing identifiers does not make work
  material personal. Use independently created personal material and synthetic
  examples; do not assume technical content has personal provenance.
- Apply these rules to code, documentation, examples, attribution, license
  notices, commit messages, author/committer identities, branches, tags, issues,
  pull requests, comments, releases, workflow logs, artifacts, and attachments.
- Before committing or publishing, verify the destination, staged or outgoing
  content, Git identity, and relevant history. Use an explicitly configured
  personal or GitHub noreply identity, never an inherited work identity.
  Removing a detail from the current tree does not remove it from history.
- Do not use unrelated work repositories or work services as source material,
  or transmit work information to external tools during a personal task.
  Keep privacy notes and audit summaries generic; do not name actual employers.
- If provenance, ownership, identity, destination, or privacy is uncertain,
  STOP before committing, pushing, or publishing and ask the maintainer.
  Keyword checks alone cannot establish that content is personal.
- Keep this policy repository-scoped. Do not modify global agent settings or
  unrelated repositories, rewrite history, delete content, or change repository
  visibility without explicit permission.
- Pass this policy to any delegated agent. These instructions are a reminder,
  not an automatic security barrier or a guarantee against leaks.
